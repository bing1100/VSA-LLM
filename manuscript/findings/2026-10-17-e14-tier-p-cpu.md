### RD-2: dictionary breadth (T4)

- **Gold partners found:**
  - base finder (33,941 surfaces): 0.116;
  - with ChEBI 255 synonyms and hyphen/case variants (65,514 surfaces): 0.116;
  - also de-hyphenating the text: 0.117.
- **Shrinking curve** (base surfaces of a random 25 / 50 / 75 / 100% of atoms, 3 seeds): 0.028 / 0.057 / 0.088 / 0.116.
  This is linear.
- **Reading:** recall equals the share of gold partners that the text names. Synonyms do not uncover hidden partners.

### RD-5: does reading snowball? (simulation, 5,000 T4 ChEBI definitions, 5 rounds, 3 seeds)

**Design:**
- Start with 25, 50 or 75% of the atoms linkable.
- Read every definition with the finder over the current dictionary and the type prior's relation.
- Add each read entry's own atom to the dictionary.

**Results:**
- The dictionary grows 0.25 → 0.28, 0.50 → 0.53 and 0.75 → 0.76, then stalls after round 2.
- Partner recall tracks the dictionary share.
- Edge precision is 0.22–0.28 even with the type prior; recall of all gold edges is 0.03–0.08.
- **Reading:**
  - Read entries are rarely the partners of other entries, so there is no snowball.
  - Most concepts a definition mentions are not in its frame: mentions are not facts.

### RD-6: the structured part of the frame (T4 held-out)

- `contains_element` (from the formula), `charge` and `branch` (from the root of the is-a ancestry) are 42.1% of the
  gold edges.
- All are recovered with recall 1.00 and precision 1.00.
- **This is by construction:** the ontology was built from the same ChEBI fields. The result quantifies the share of the
  frame that only structured data supplies.

### RD-3 teacher frames

Claude read the 341 T4 held-out definitions (43 calls, $1.96). The frames feed the queued RD-3 jobs.

### Answers to the author's questions (evidence so far)

- **A larger ontology?** More relation types, yes, especially for MeSH, where 42% of statements have no relation. A
  larger dictionary or more synonyms, no (RD-2).
- **Picks up steam?** Not by growing the dictionary from read entries (RD-5).
- **The model not smart enough?** Answered by RD-3 (queued) and RD-9 (tier F).
- **Can read facts be used at all?** Answered by RD-4 (queued; the decisive experiment for self-learning).

## Part 2 — the algebra and the soft settings (LG-A, LG-C CPU parts, LG-P3)

**Setup:** 3 seeds (A11: seed 1) and random vectors unless stated otherwise. Full tables are in
`experiments/e14-logic/runs/lga/{report.md, *.csv}`.

### Gate G0 (pre-registration §3): passes

- **Chains:** depth 3 at load 8 (the T4 mean) scores 1.00 from width 512. Width 256 scores 0.94.
- **Rules from examples:** an inverse rule estimated from k = 3 examples scores 1.00 on unseen entities at width 1,024.

### A1: one rule as one vector

- **Rules that move every part of the fact work.** An inverse rule with a renamed predicate, or rotating three
  arguments, gives 1.00 at widths 1,024 and 4,096 from k ≥ 3 examples. At width 256: 0.81. One example is not enough
  (0.07 at 1,024).
- **Rules that keep part of the fact fixed are impossible for one convolution.**
  - Same-predicate symmetry and sub-relation with the same arguments score ≤ 0.16 at every width, whether written by
    hand or estimated.
  - A single circular-convolution map that leaves one role–filler pair unchanged must be the identity, so it cannot also
    move the other pairs.
  - With separate premise and conclusion roles (C4) the same rules work. The limit applies to rewriting a fact in place
    within one role set.
- **Applied to a frame of 8 bundled facts, every rule fails** (≤ 0.02 at all widths). The map transforms every fact in
  the bundle, so rules need one fact per vector (a fact memory), not entity frames.
- **Correlated and trained fillers** (the survey's warning; prediction confirmed). Inverse rule with k = 10:

  | Fillers | Width 256 | Width 1,024 |
  |---|---:|---:|
  | random | 0.81 | 1.00 |
  | correlated (cosine 0.3) | 0.55 | 1.00 |
  | trained T5 C5 rows (native width 256) | **0.60** (−0.21 against random) | — |

### A2: chains executed by unbinding with clean-up per hop

**Accuracy at depth 3** (HRR, fixed load, clean-up over all entities):

| Width | Load 4 | 8 | 16 | 32 |
|---|---:|---:|---:|---:|
| 256 | 1.00 | 0.94 | 0.28 | 0.01 |
| 512 | 1.00 | 1.00 | 0.95 | 0.25 |
| 1,024 | 1.00 | 1.00 | 1.00 | 0.94 |
| 2,048 | 1.00 | 1.00 | 1.00 | 1.00 |

- **Heavy-tailed loads** cost about 0.08 at width 1,024 and load 16 (0.92). Typed clean-up recovers 0.02–0.04.
- **At depth 8, width 2,048:** 1.00 with fixed loads; about 0.79 with heavy-tailed load 32.
- **The algebra does not matter:** HRR, MAP and FHRR are indistinguishable.
- **One global bundle of all facts: 0.00** at every width. Storage must be per entity.

### A3: joins (the Datalog fragment)

- **Method:** edges decoded from per-entity stores with a calibrated presence threshold, then rules applied.
- **Decoded base edges:** F1 0.97 (width 256), 1.00 (1,024).
- **Derived closure with 20 rules:**
  - width 1,024: F1 1.00 for every shape (chain, star, inheritance, conjunction, negation as failure, recursion);
  - width 256: 0.94–0.97, and **recursion 0.74**, because errors compound through repeated derivation.

### A4: nesting and order

- **Nested role–filler terms without clean-up:** 0.91 at depth 4 (width 256), 1.00 at 1,024. With clean-up per level:
  1.00.
- **Order:** f(g(a)) against g(f(a)) is 0.50–0.54 with circular convolution (commutative, as predicted). With a fixed
  random permutation it is 1.00. A cyclic shift does not help, because it commutes with convolution.
- **Argument swaps in 2–5-argument facts:** 1.00.

### A5: connectives

- **Negation as failure** by a calibrated threshold:
  - accuracy 0.96 (width 256, load 8), 0.86 (256, load 16), 1.00 (1,024);
  - calibration error (ECE) 0.03–0.11.
- **k-of-n matching AUC:** ≥ 0.94.
- **Existence queries AUC:** ≥ 0.98.

### A6: numbers (fractional power encoding)

- **Exact decode of 0–100:** 0.74 at width 256, 0.96 at width 1,024.
- **`x ≤ t`:**
  - decode then compare: ≥ 0.999;
  - a range bundle: 0.93–0.95 at width 256, 0.99–1.00 at 1,024.

### A7: decision trees and lists

- **Node memory and the flat path bundle:** 1.00 to depth 8 (width 256 at depth 4: 0.98).
- **One nested vector:** falls from 0.82–0.90 at depth 2 to 0.23 at depth 8 (chance 0.25 with 4 options in many
  trees).
- **Numeric tests:** the same pattern.
- **With 10% of input attributes wrong,** every exact method equals the exact executor run on the noisy record (0.89 at
  depth 4, 0.79 at depth 8). The soft path bundle gives **no robustness gain**: it follows whatever the noisy record
  satisfies.
- **Decision lists to length 12:** ≥ 0.99.

### A11: the trained T4 store's own rules (C5 s1)

| Rule | Decode, held-out (zero-shot) | Decode, seen |
|---|---:|---:|
| conjugate acid ↔ base (inverse) | 0.68–0.77 | 0.81–0.85 |
| enantiomer, tautomer (symmetric) | 0.60–0.61 | 0.71–0.80 |
| `is_a` at 2 hops through the parents' own stores | precision 0.94, recall 0.94 | 0.91 / 0.92 |

- **Zero-shot composed vectors chain as well as seen ones.**
- **The converse fact is in the ontology for only 6–16% of cases.** Leaf chemicals are not atoms of the T4 dictionary,
  so a derived converse fact cannot be written into T4 frames. A separate derived-fact memory is needed.

### A12: baselines on the A3 world

- **AMIE-style mining** recovers 3 of 3 planted chain rules.
- **RotatE / ComplEx** on derived facts for seen entities: hits@1 0.007 / 0.002, hits@10 0.10. They do not learn
  compositions of random relations from this data, and they cannot represent unseen entities.
- **The VSA executor, given the rules:** 1.00. This is not a learning contest: the executor is told the rules.

### LG-C, CPU parts: the "soft" settings, where the store should beat symbols — no advantage yet

| Setting | VSA store | Fair symbolic baseline |
|---|---:|---:|
| C1 similarity completion of a mostly-true type property | 0.74–0.79 | rule induction (majority of the type) 0.75–0.81 |
| C2 aliases: 1–2 edits / abbreviations | 0.99–1.00 / 0.97–0.98 | prefix + edit distance 1.00 / 0.996 (plain edit distance on abbreviations: 0.23) |
| C3 wrong facts injected at 10% / 30% (closure F1) | 0.81 / 0.50, with or without abstention | Datalog 0.81 / 0.50 |
| C4 rules from k = 1 / k ≥ 3 examples | 0.63–0.93 / 1.00 | AMIE-style mining 1.00 / 1.00 |

- **Margins detect decoding noise, not wrong facts** (C3).
- **On clean synthetic data, symbolic induction is as good or better** (C4).
- **The mapping vector "solves" the chain rule** without checking that the middle entity is shared (proposal §3.10). A
  join test with mismatched middles belongs to tier F.

### LG-P3: premise selection by VSA retrieval

Recall@5 of the matching rules is 1.00 with 50 and 500 clauses at width 1,024. Each rule vector holds two bindings, so
the test is easy; tier F stresses it.

### Reading, for the proposal

1. **The algebra executes structured rules reliably** at widths ≥ 1,024 and realistic loads: chains, joins, negation,
   numbers, trees. It does so when each entity, node or fact has its own store and every step is cleaned up.
2. **The main risks are known and measured:**
   - capacity (load ≥ 16 at width 256);
   - heavy-tailed degrees;
   - correlated, trained fillers at small widths;
   - mapping vectors' structural limits (fixed-point rules; whole frames).
3. **In every soft setting tested so far on the CPU, the store only ties a fair symbolic baseline.** Gate G2's
   advantage is not visible on the CPU.
4. **The case for the store therefore rests on the model-facing tests** (LG-B/C/D, LG-P, queued) and on compactness
   and edit propagation, not on better reasoning.
