# T2 developer tools (E8, WP-T2)

API symbols as concepts — schemas and type signatures as frames — linked into documentation, code
comments and examples. Two sub-ontologies share one relation set and one atomic dictionary:

- **private libraries** (16 seeded libraries, invented names): the contamination-free core — no
  pretrained host can know the symbols, so held-out and zero-shot results are clean on every host;
- **real libraries** (20 permissively licensed Python packages incl. the standard library, and the
  Node.js API): realistic documentation text and a natural long tail (contaminated for pretrained hosts:
  only the private symbols count for zero-shot claims there, E4.6 / E5.4).

Two builds from the same documents, holdout and items: `runs/v1` (SmolLM2 tokenizer, 100M tokens,
SmolLM2-135M continued pretraining, `t2.yaml`) and `runs/v1-gpt2` (GPT-2, 300M tokens, the 50M
from-scratch run, `t2-gpt2.yaml`).

## Linking code symbols: the `identifier` alias normalization (new)

`span_channel.normalize_alias` turns `_` into a space (the WordNet lemma convention), so a snake_case
alias such as `fetch_record_batch` becomes `fetch record batch` and never matches code. T2 links with a
new, opt-in alias normalization: `AliasTable.from_pairs(pairs, normalization="identifier")` lowercases
and collapses whitespace but keeps `_` (and `.`), so `fetch_record_batch(` and
`lib.module.fetch_record_batch` link to the symbol (test: `tests/test_t2_devtools.py`). The linker is
unchanged; the default mode, every existing table digest and every recorded corpus are unchanged
(`AliasTable.normalization` defaults to `"default"` and enters the digest only when it is not the
default). `track_corpus.py` takes it from `linker.alias_normalization`, records
`alias_normalization` in `ontology.pt` and writes the table itself next to it (`alias_table.json`,
read by `channel_probes.resolve_alias_table`), so no consumer can rebuild the table in the wrong mode.

Effect on T2: with the default mode only **49.7%** of the 55,412 T2 symbols have an alias that can
occur in code at all (41.6% of private symbols — none of the 6,795 Python snake_case functions,
methods and constants — and 51.9% of real symbols); with `identifier`, 100%. On the same 2,000
evaluation documents (`runs/*/linking_by_normalization.json`) linked concepts rise from 3,793 (6.8%) to
7,096 (12.8%) and span occurrences from 27,078 to 36,531 (covered-token fraction 0.26 → 0.38 with
SmolLM2, 0.21 → 0.31 with GPT-2).

**For WP-E5 (`experiments/e5_zeroshot.py`, scenario `c6_devtools`):** C6 symbols are snake_case, so
its alias table must be built with `AliasTable.from_pairs(..., normalization="identifier")` (or, for
T2 symbols, loaded from `alias_table.json` / `load_alias_table`, which keeps the mode); any corpus or
probe text it links must use that table. Nothing else changes (same `CausalLinker`).

## Recipe (E8 steps 1–3, 5, 7)

1. **Private libraries** (`generate_private_libraries`, the scaled C6 generator; C6 v1 still
   regenerates bit-identically, tested). 16 libraries (11 Python-style, 5 TypeScript-style), 11,750
   symbols: 16 packages, 210 modules, 1,563 classes, 208 exceptions (a hierarchy per library), 3,203
   functions, 6,342 methods, 208 constants. Schema relations: kind, library, language, member_of,
   category (16 areas), purpose, returns, takes (parameter types), has_param, raises, inherits,
   overrides, deprecated_by, calls, since, status. Identifiers follow each language (Python snake_case,
   TypeScript camelCase, CamelCase classes, UPPER_SNAKE constants), built from invented stems that are
   never a WordNet lemma or a word of 20,000 FineWeb-Edu documents, the real-library docs or the
   generator's own source (269,377 forbidden words), and **prefix-free** (the linker is prefix-causal).
   Overriding methods share their base method's name (the only polysemous private aliases).
2. **Real libraries** (`data/api_docs.py`, frozen snapshot `real-v1`, hash `553d89cd…`): 43,662 public
   documented symbols (stdlib 6,313 from the inventory; transformers 10,982, sympy 7,666, torch 3,616, …;
   Node.js 1,270), 44,880 documentation units (47.9M characters: qualified signature line, docstring,
   source comment lines; CPython doc sections; Node API entries). Schemas from code: parameters and
   annotations, return annotation or numpydoc/Google "Returns", raised exceptions (`raise` statements and
   "Raises" sections), resolved base classes, overridden base methods, deprecations, `versionadded`.
   Aliases: public dotted paths incl. re-exports (`torch.nn.Module`), `np.`/`pd.`/`nx.`/`plt.`/`nn.`
   forms, and bare CamelCase class names that are not English words; never an undotted name.
3. **Ontology** (`ontologies/devtools.py`): 55,412 concepts (11,150 private + 43,662 real; the 600
   zero-shot symbols are added as synthetic concepts), 16 relations, 8,192 atomics (fixed: kinds,
   libraries, languages, categories, purposes, statuses; then the most used symbol, module, type,
   parameter and version fillers; out-of-budget fillers fall back to their kind / library), ≤ 16
   edges per frame, 217,493 aliases, 55,227 link entries.
4. **Documents** (`docs-v1`, shared by both builds; `documents_summary.json`). Private: API reference
   entries, module source files with docstrings, comments and bodies, type stubs (`.pyi` / `.d.ts`),
   usage examples, tutorials, Q&A threads, issue reports with tracebacks, changelogs, migration guides,
   code reviews, READMEs. Focus symbols follow `(rank + 60) ** -1.6` (no symbol takes more than ~1% of
   the documents); the last 4 libraries are **niche** (documented 100× less per symbol), which keeps a
   private rare tail at both corpus sizes. Real units are grouped by page (≤ 8,000 characters); 8% of
   units (sha256 bucket) are evaluation-only. The two streams are interleaved by characters so every
   prefix has the same composition: training 439.7M characters = 396.1M private (90%) + 43.6M real (10%,
   every real training page once); evaluation 22.0M characters (18.6% real).
5. **Holdout** (fixed by the track, frozen before any build with `--stage freeze` and pinned as
   `data.expected_holdout_sha256` = `75ee2217be97bd9d…` in both configs; `items/holdout_concepts.txt`):
   1,078 concepts = 899 private (10% of functions, methods and leaf classes, stratified by Zipf rank; a
   held-out class takes its methods) + 179 real (10% of leaf symbols with ≥ 5 alias occurrences whose
   aliases are neither a prefix of, nor a whole-word part of, another alias; stratified by log2
   occurrences). Held-out symbols never occur in training text: private clauses naming one are dropped,
   real training units and any training document lose every line containing a held-out alias (8,864
   lines). Node- and alias-disjoint (checked with `t1_open_corpus.assert_alias_disjoint`). **Zero-shot**
   (E5.4 "new API symbols"): 600 private symbols (functions, classes with methods, methods on existing
   classes) defined only by schemas over existing symbols, in no document, referenced by nothing
   (`items/synthetic_concepts.jsonl`, sha256 `d0e26c8f…`). **Leakage audit: 0** (no held-out or zero-shot
   alias under the linker's rule, no held-out private stem as a word, in training text; no zero-shot
   alias in evaluation text).
6. **Corpora**, with the `identifier` normalization:

   | build | tokenizer | train tokens (domain / general) | domain eval tokens | general eval tokens |
   |---|---|---:|---:|---:|
   | `runs/v1` | SmolLM2 | 100,001,973 (50,000,350 / 50,001,623) | 6,000,094 | 4,998,786 |
   | `runs/v1-gpt2` | GPT-2 | 300,004,714 (150,000,089 / 150,004,625) | 6,000,595 | 4,945,038 |

7. **Cardinality and feasibility** (`runs/*/report.md`, `cardinality.json`, `feasibility.json`,
   `feasibility_strict.json`):

   | build | FEASIBILITY (C7, ≤ 1,024 windows) | WP-T1 bar (whole 6M-token split) |
   |---|---|---|
   | SmolLM2 | **feasible at ℓ_min = 2 with 512 windows** (416 held-out entries / 1,053 spans; 792 rare entries / 1,755 spans; covered fraction 0.38) | **feasible at ℓ_min 1–4 with 3,072 windows**: 739 held-out entries ≥ 5 occ. / 12,864 occ.; 2,929 rare entries / 18,501 occ. |
   | GPT-2 | **feasible at ℓ_min = 2 with 1,024 windows** (575 / 1,866; 1,026 / 2,115; 0.32) | **feasible at ℓ_min 1–4 with 3,072 windows**: 677 / 10,932; 2,903 / 12,410 |

   Identifiers are long in subtokens, so ℓ_min = 1, 2, 3 give nearly the same span sets. Rare = training
   frequency 1–9 at ℓ_min in that build; "unseen" linked entries (frequency 0, not held out) are reported

   text is dense in identifiers.
8. **Items** (`items/`, hashes in `items/holdout.json`; identical for both builds — mention counts come
   from the shared document file, not from a tokenizer; `mentions` = alias occurrences in the whole

   library and share the answer's surface shape (builtin type / dotted path / CamelCase / snake_case /

## How much domain text is realistic

The private stream is templated. Measured along the stream in 20M-character chunks, the share of word
8-grams never seen earlier is 28% in the second chunk (20–40M characters), 18% around 100M and 11% in
the last chunk (≈ 396M); FineWeb-Edu stays at 99.6%. All 396M private characters contain 6.0M distinct
8-grams — as many as ≈ 37M characters (≈ 8M GPT-2 tokens) of FineWeb-Edu — and state 144,437 schema
facts, ≈ 940 GPT-2 tokens per fact. The real-library text (47.9M characters, ≈ 16–18M GPT-2 tokens) is
all the permissively licensed documentation used here, each page once. So the realistic non-redundant
size of the domain text is ≈ 40M characters of private text (after which > 70% of every new chunk's
8-grams have been seen before) plus the real text, i.e. ≈ 30M GPT-2 tokens; the 150M-token domain half
of the GPT-2 run (and the 50M of the SmolLM2 run) is reached with ~90% repetitive synthetic text that
re-states the same facts in new combinations. This follows the E8 recipe (50/50 at 300M) as specified;
alternatives for a later revision are a smaller domain share for the from-scratch run or more real
documentation (e.g. package docs from upstream repositories).

## Build (≈ 15 min CPU in total, ≤ 3 tokenizer workers)

```bash
# 1. real-library snapshot (86 s; rebuilt twice, identical; pinned as real_libraries.snapshot_sha256)
PYTHONPATH=src python -m vsa_embed.tracks.devtools --config experiments/t2-developer-tools/t2.yaml --stage snapshot
# 2. documents + frozen holdout (≈ 100 s; prints the holdout sha256 pinned as data.expected_holdout_sha256)
PYTHONPATH=src python -m vsa_embed.tracks.devtools --config experiments/t2-developer-tools/t2.yaml --stage freeze
# 3. corpora, cardinality, feasibility, items (SmolLM2 4 min 37 s, 2.9 GB peak RSS; GPT-2 6 min 44 s, 3.5 GB)
PYTHONPATH=src python -m vsa_embed.experiments.track_corpus \
  --config experiments/t2-developer-tools/t2.yaml --output experiments/t2-developer-tools/runs/v1
PYTHONPATH=src python -m vsa_embed.experiments.track_corpus \
  --config experiments/t2-developer-tools/t2-gpt2.yaml --output experiments/t2-developer-tools/runs/v1-gpt2
```

Large outputs: `~/data/vsa-llm/tracks/t2-devtools/` — `raw/` (downloads), `real-v1/` (snapshot, 14 MB),
`docs-v1/` (documents, libraries, mentions, 128 MB), `v1-smollm2/` (535 MB) and `v1-gpt2/` (1.5 GB) with
`train/`, `eval/`, `eval-general/`, `ontology.pt` and `alias_table.json`.

For training, point the trainer at `data.train`, `data.eval` and `data.ontology` of a build;
`ontology.pt` has the C3 keys plus `heldout_real_entries` (the 1,078 held-out entries; "real" in the
track-builder sense, i.e. not synthetic), `synthetic_entries` (the 600 zero-shot entries),
`train_frequency_by_min_subtokens` and `alias_normalization: "identifier"`. Use 3,072 evaluation
windows to meet WP-T1's bar (the trainer default 1,024 meets the C7 criterion).

## Decisions and deviations

- **Identifier alias normalization** (orchestrator request): opt-in mode, default untouched; T2 only.
- **Two configs** (`t2.yaml`, `t2-gpt2.yaml`) instead of one, both through `track_corpus.py`, sharing
  documents (`devtools.docs_dir`) and a pinned holdout; the SmolLM2 build also uses the C3 general stream
  and its 5,000 evaluation documents (T3–T6 use shard `000` and 2,000 documents) so both T2 builds share
  one general evaluation set.
- **Real "JS" library** = the Node.js API reference; npm package docs were not fetched.
- **Real held-out symbols** follow the private rule (never in training text; lines dropped) rather than
  C3's (in text, unlinked), so the held-out stratum means the same for both sources.
- **Niche libraries** and **shape-matched distractors** were added after a first full build (discarded,
  never trained on) showed no private rare tail at 150M domain tokens and form-revealing distractors;
  symbols and holdout did not change.
- New optional `track_corpus` keys (no effect on T3–T6 configs): `data.expected_holdout_sha256`,
  `feasibility_strict`, `linker.alias_normalization`.
